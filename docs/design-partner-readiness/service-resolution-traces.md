# Service-Resolution Traces

**Status**: Concept demonstrator. Every number and quote below is real output from the
current deterministic pipeline (`lib/retrieval.ts`, `lib/routing.ts`, `lib/escalation.ts`
on branch `feat/d5-d7-service-resolution-readiness`), generated by directly invoking those
functions and reproduced here verbatim — nothing is fabricated or hand-written to look
plausible. Queries are synthetic/demonstration questions, not real student input; none was
collected from, or entered by, an actual student. This is a demonstration of routing and
escalation mechanics, not counselling, crisis intervention, or a live service.

Reproduce any trace yourself: run `npm run dev`, then `GET /api/dev/routing?q=<query>`
with any query below (development mode only, per `NODE_ENV` gating).

| Field | Value |
|---|---|
| 1. Query | "How do I apply for a student loan or financial aid?" |
| 2. Source ID(s) | **None curated.** `NBCC-SS-006` (Student Loans) is approved but not curated — the same disclosed gap as Trace 4. |
| 3. Retrieval rationale | Real output: top match is NBCC-SS-002 (score 32, academic_support), the wrong source, for the same reason — no financial-aid content exists in the curated corpus. |
| 4. Journey | Retrieval-derived journey is (incorrectly) `academic_support` today. Routing *logic* is separately proven correct: `tests/routing.test.ts` ("maps financial_support domain to financial_support journey"). |
| 5. Escalation decision | Depends on phrasing. A neutral query ("How do I apply for a student loan?") does not trigger escalation today (`should_escalate: false`) — it would incorrectly present as a resolved academic_support query rather than escalating. A query using explicit decision language ("What are my chances of loan approval?") **does** escalate, via `personalized_decision` — but its target resolves to whatever journey was (incorrectly) derived, in this case `NBCC-SS-002` (Student Success Coaching), **not** the financial-aid-specific contact. |
| 6. Trigger / target | For the decision-language phrasing: trigger `personalized_decision` (matched term: "loan approval"), target `NBCC-SS-002` — **this is a real, additional limitation surfaced by this trace, distinct from Trace 4**: unlike `crisis_or_safety` and `accommodation_request`, the `personalized_decision` trigger's target is journey-derived, not hardcoded, so it inherits the content-coverage gap's misrouting. |
| 7. Learner-facing next step | Today: an incorrect or absent informational result, and — for decision-phrased queries only — an escalation to the wrong contact. This is the most significant of the five traces' limitations and is called out explicitly rather than minimized. |
| 8. Provenance / limitation | Same disclosed gap as Trace 4, compounded by `personalized_decision`'s non-hardcoded target. Curating `NBCC-SS-006` closes the retrieval/journey gap; whether `personalized_decision`'s target should also be hardcoded per-domain (like `crisis_or_safety` and `accommodation_request`) is a design question worth revisiting once financial content exists, not decided here. |
| 9. Evidence reference | `tests/routing.test.ts` (routing-logic correctness), `tests/escalation.test.ts` (personalized_decision suite), `knowledge/sources.yaml` (NBCC-SS-006 catalogue entry, approved but uncurated). |
