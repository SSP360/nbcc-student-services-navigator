# Baseline / Value Worksheet

**Status**: Concept demonstrator. **No value claim in this document has been validated
with any institution.** This worksheet exists to define categories precisely — so that
if a design partner later provides real baseline data, the resulting analysis does not
accidentally conflate different kinds of value. No numbers are asserted here; every cell
below is a hypothesis category and a data requirement, not a result.

## Why This Distinction Matters

A common analysis error is treating "staff spent less time on X" as if it were "the
institution saved cash." These are different claims requiring different evidence, and
conflating them is exactly the kind of unsupported claim `AI_OPERATING_INSTRUCTIONS.md`'s
prohibition on inventing outcomes exists to prevent. This worksheet keeps them separate by
construction.

## The Four Categories

| Category | Definition | What would be required to claim it | Claimed in this document? |
|---|---|---|---|
| **Cash savings** | An institution actually spends less real money after adoption (e.g., a role is not backfilled, a contract is reduced). | A documented before/after budget line from the institution itself, attributable to this specific change, over a defined period. | **No.** No institution has provided budget data. |
| **Capacity release** | Staff time is freed from repetitive triage/routing work, available for other work. | Aggregate staff time-on-task data (see `measurement-design.md`), collected with staff consent. | **No.** Not measured; not claimed. Capacity release must never be reported as cash savings unless an institution separately confirms an actual budget change resulted from it — that confirmation does not exist here. |
| **Cost avoidance** | A future cost that would otherwise have been incurred (e.g., an anticipated hire) is not incurred. | A specific, documented institutional plan that was avoided, confirmed by the institution. | **No.** No such confirmation exists. |
| **Retention or revenue-protection hypothesis** | A student who might otherwise have withdrawn stays enrolled because they reached the right support faster. | Longitudinal enrollment data correlated with support-seeking behavior, which requires real student data this project explicitly does not collect (`policies/DATA_POLICY.md`) and is not designed to collect even in a future pilot without a separate, explicit scope decision. | **No, and not currently measurable within this project's data boundaries.** This remains a hypothesis to test only if an institution separately undertakes its own correlated analysis using its own data governance — not something this demonstrator or a bounded pilot would produce. |

## What This Worksheet Is For

When a design partner is ready to discuss value, use this table to ask: *which category
are we actually talking about, and what evidence would we need to support that specific
category?* Do not let a capacity-release observation ("staff reported spending 20% less
time on repetitive routing questions") be restated as a cash-savings or retention claim
without the additional, category-specific evidence the table above requires.

## Explicitly Not Done Here

- No dollar figure is estimated or implied for any category.
- No percentage improvement is claimed for any category.
- No claim is made that a pilot is guaranteed to produce evidence for any category —
  that is exactly what the pilot's success measures (`pilot-charter.md`) exist to test,
  not assume.
