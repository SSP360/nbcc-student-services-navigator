## Curated File Format

One JSON file per source under `knowledge/curated/`:

- `knowledge/curated/NBCC-SS-001.json`
- `knowledge/curated/NBCC-SS-002.json`
- `knowledge/curated/NBCC-SS-005.json`

Each record carries: `source_id`, `title`, `url`, `domain`, `campuses`, `language`,
`source_type`, `authority`, `review_status`, `retrieval_timestamp`, `retrieval_method`,
`http_status`, `content_length`, `extracted_text`, `retrieval_error`. Metadata fields mirror
`knowledge/sources.yaml` field names so provenance is a direct match, not a transformation.

No database was introduced. The format is plain JSON, readable with any text editor, and
requires no new runtime dependency to inspect.

## Extraction and Noise Handling

Reused the Day 1 extraction pattern: parse HTML with jsdom, remove `<script>`, `<style>`,
`<nav>`, `.sidebar`, `.menu` elements (plus `footer`, `.cookie-banner`, `.cookie-consent` added
for the curation script to reduce footer/cookie noise), then take `body.textContent`, trim and
filter blank lines.

**Observation**: extracted text still includes some footer boilerplate (campus addresses,
social media links, copyright line, contact staff listings). This is genuine, unaltered NBCC
content — nothing was rewritten, summarized, or reworded — so it satisfies the "do not alter
institutional meaning" constraint, but it is noisier than an ideal curated record. This is
flagged as a known limitation below rather than silently fixed, since improving noise removal
further risks trimming legitimate contact information that later journeys may need.

No JavaScript-rendered or dynamic content was encountered; all three pages returned complete
HTML on first request with no client-side rendering dependency.

## Validation Approach

`lib/curated-sources.ts` provides:

- `loadCuratedSourceIds()`, `loadCuratedSource()`, `loadAllCuratedSources()` — loader functions
- `validateCuratedSource()` — per-record validation
- `validateCuratedCorpus()` — cross-record validation (duplicate ID detection)
- `traceCuratedSourceToCatalogue()` — confirms `source_id` + `url` match a `sources.yaml` entry

Validation confirms, per the acceptance criteria:

- Missing required metadata (title, domain, url, campuses, language, authority, review_status)
- Duplicate source IDs across the corpus
- Empty extracted text
- Invalid URL syntax
- URLs outside the approved NBCC allowlist (`nbcc.ca`, `documents.nbcc.ca`)
- Non-HTTPS URLs
- Content below the 500-character minimum usable-content threshold
- Invalid `retrieval_method` values
- Non-ISO-8601 `retrieval_timestamp` values

All checks are covered by dedicated unit tests in `tests/curated-sources.test.ts`, including a
test that runs `validateCuratedCorpus()` against the real on-disk corpus and asserts zero
issues.

## Known Limitations

1. Extracted text includes some non-essential footer content (addresses, social links,
   copyright) alongside the substantive service information. This is real NBCC content, not
   fabricated, but is not fully "clean" prose.
2. No automatic re-curation on a schedule; curated files are a point-in-time snapshot of
   `retrieval_timestamp`.
3. Curated content is not yet consumed by any retrieval/search feature — this increment only
   establishes the verified corpus and its validation, per D2-01 scope.
4. `.claude/` directory and an unrelated `package.json` working-tree change were found on the
   branch at session start and were deliberately left untouched, as they are outside D2-01's
   scope.
